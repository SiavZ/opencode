# Runbook: install, upgrade, rollback (Rust `opencode`)

Scope: the GitHub release archives produced by `cargo xtask distribution build`, the container in `rust/distribution/Dockerfile`, and the Nix derivation. Baseline behavior: `install` (curl script, installs to `$HOME/.opencode/bin`, picks `opencode-<os>-<arch>[-baseline][-musl]`), npm/Homebrew/AUR formulas generated by `packages/opencode/script/publish.ts`.

## Preconditions

- Release directory with `SHA256SUMS`, archives and `*.cdx.json`. Run `cargo xtask distribution verify --dir <dir>` before anything is published or installed.
- Know the data dir: `$XDG_DATA_HOME/opencode` (default `~/.local/share/opencode`), which holds `opencode.db` (SQLite in WAL mode, `packages/core/src/database/database.ts:27,53`) and `auth.json` (mode 0600).

## Install (archive)

1. Pick the asset with the same logic as `install:117-168`: musl if `ldd --version` reports musl, `-baseline` on x64 without AVX2.
2. Download the archive and `SHA256SUMS`, then run `sha256sum -c --ignore-missing SHA256SUMS` (macOS: `shasum -a 256 -c`).
3. Extract. The archive holds only `opencode` (`opencode.exe` on Windows). Install it to `$HOME/.opencode/bin/opencode` with mode 0755.
4. Verify: `opencode --version` prints the release version. **Today the Rust CLI exits 2 with "not yet ported" (Phase 09), so this check cannot pass yet.**

## Install (container)

```sh
docker build -f rust/distribution/Dockerfile --platform linux/arm64 -t opencode-rust:<ver> rust
docker volume create opencode-data
docker run -d --name opencode -p 127.0.0.1:4096:4096 -v opencode-data:/data opencode-rust:<ver>
docker inspect --format '{{.State.Health.Status}}' opencode   # expect healthy
```

In production, deploy by digest (`image@sha256:...`) and never by mutable tag.

## Upgrade

1. Back up first: follow `sqlite-backup-restore.md` (online backup of `opencode.db`) and copy `auth.json`.
2. Stop the old process (`SIGTERM`; containers use `STOPSIGNAL SIGTERM`), then confirm with `pgrep opencode` that no writer remains.
3. Replace the binary atomically. Write `opencode.new` in the same directory, then `mv -f opencode.new opencode`. Keep the previous binary as `opencode.prev`.
4. Start the new version. Schema migrations run on open. Watch the logs for migration errors.
5. Verify: `--version`, `GET /global/health` returns 200, an existing session lists, and `PRAGMA integrity_check` on a copy of the DB returns `ok`.

## Rollback

1. Stop the new version.
2. If the new version ran a schema migration, **restore the pre-upgrade DB backup**. Old binaries are not guaranteed to read a migrated DB. Data written after the upgrade is lost, so tell the users affected.
3. `mv opencode.prev opencode` (container: redeploy the previous digest with the same volume).
4. Verify as in step 5 of the upgrade.

## Verification checklist

- [ ] `distribution verify` passes on the release dir.
- [ ] Checksums verified on the client.
- [ ] Health is 200 and `--version` matches.
- [ ] A backup was taken before the upgrade and was restorable (see that runbook).

## What is untested

- Every `--version` and health step: the Rust CLI and server are not ported yet (Phase 09/06).
- Migration compatibility between versions: no two Rust releases exist yet.
- Homebrew, AUR, npm and the `install` script against Rust artifacts: no release exists (Phase 94).
- Windows install paths and Authenticode, macOS notarization/Gatekeeper.
- Exercised so far: archive naming and checksum verification, and container build plus non-root `/data` on linux/arm64.
